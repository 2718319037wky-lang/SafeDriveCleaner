引擎的硬性质

界面只能做减法。清理时界面只把勾选的路径字符串交给引擎；引擎会重新完整扫描一遍，再与勾选结果取交集，最后对每一条重跑完整保护裁决。
因此界面能做的只有「从引擎自己算出的候选里减掉一些」——永远无法让引擎去删一个它自己不会产生的目标。
默认只读
不加 -Mode Clean 永远不删任何东西，第一次跑就是纯扫描 + 出报告
不跟随链接
目录联接与符号链接一律跳过，避免 D:\cache → C:\Users\… 这类链接导致跨盘误删
回收站删除
底层调 SHFileOperation + FOF_ALLOWUNDO，全程无弹窗、不阻塞，删错了可以还原
年龄阈值
每条规则带 minAgeDays，只清「最后修改早于 N 天」的内容，避免删掉正在使用的缓存
执行前复查
扫描到执行之间会重跑存在性 + 实际类型 + 完整保护裁决，防住 TOCTOU 掉包
四份留痕
控制台、日志、JSON 报告、HTML 报告，每一条操作都可事后审计

刻意不做的事

注册表清理
与系统耦合面太大，一旦清错无法用回收站还原，与本项目「可控可还原」的定位不符
卸载残留清理
同上，误判代价远高于收益
压缩包一律不碰
.zip / .7z / .rar 全部列入保护——会漏掉一些本可安全清理的压缩缓存，这是刻意的保守取舍
非 Windows 平台
依赖 SHFileOperation 与回收站语义，仅支持 Windows
